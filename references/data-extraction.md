# 数据抽取与字段识别

## 1. 典型表结构

个人资产负债表的通用形态（按月分 sheet，sheet 名形如 `资产&负债-202609`）：

```
┌─ 我的资产 ──────────────────────────────────────────────────────┐
│ 资产 | 分类 | 风险 | 名称 | 成本 | 上月价 | 最新价 | 上月收益      │
│      |      |      |      | 总收益 | 收益率 | 买入来源 | 月总收益 │
│      |      |      |      | 审视结论 | 备注                      │
│  股票 / 基金 / 债券 / 现金  ← 一级分类只在该组首行出现，下面留空   │
│  总计 行                                                         │
│  房产 行（在总计之后，通常不计入总计）                            │
├─ 我的负债 ──────────────────────────────────────────────────────┤
│ 负债 | 分类 | 日期 | 名称 | 原负债 | | 现负债 | | 已结清 | 结清率  │
│      | 贷款来源 | 备注                                           │
│  房贷 / 学贷 / 信用卡 / 花呗 / 白条                               │
│  总计 行                                                         │
├─ 赚钱效率 ──────────────────────────────────────────────────────┤
│ 工资收入 | 被动稳定收入 | 被动风险收入 | 创业收入                  │
│ 被动/主动收入占比 | 月天数 | 效率                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 解析原则

### 必须按表头文字定位，不按列号
各月列数会变化。正确做法：

```python
HEADER_ALIAS = {
    '成本':      ['成本', '投入', '买入成本', '本金'],
    '最新价':    ['最新价', '现价', '市值', '当前市值'],
    '上月价':    ['上月价', '上月市值'],
    '总收益':    ['总收益', '累计收益', '累计盈亏'],
    '上月收益':  ['上月收益', '月收益', '当月盈亏'],
    '收益率':    ['收益率', '累计收益率'],
    '风险':      ['风险', '风险等级'],
    '现负债':    ['现负债', '剩余负债', '未还'],
    '原负债':    ['原负债', '初始负债', '贷款总额'],
    '已结清':    ['已结清', '已还', '已偿还'],
}
```

### 一级分类需要向下填充（forward fill）
`资产` 列只在每组首行写「股票」「基金」「债券」「现金」，下方为空。解析时必须 ffill。

### 识别"僵尸行"
`成本 == 0` 且 `最新价` 为空 → 已清仓的历史记录，**不计入任何统计**，但要统计数量（用于「表格卫生」问题项）。

### `#DIV/0!` 处理
已清仓行的收益率普遍是 `#DIV/0!`。统计其出现次数，作为数据质量问题之一，但不要让它污染数值计算。

## 3. edsdk 调用范式（首选通道）

```bash
SK="/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/tencent-local-office-edit"

# ① 后台打开（返回的 file_id 就是路径字符串本身）
cd "$SK" && python3 edsdk.py call open_file file_path="/abs/path/我的资产与负债.xlsx"

# ② 列出所有 sheet，拿 sheet_id / used_row_count / used_col_count
python3 edsdk.py call sheet_get_sheet_info file_id="/abs/path/我的资产与负债.xlsx"

# ③ 逐 sheet 取 CSV
python3 edsdk.py call sheet_get_cell_data file_id="/abs/path/我的资产与负债.xlsx" \
  sheet_id=000001 start_row=0 start_col=0 end_row=61 end_col=14 return_csv=true
```

`sheet_id` 是 6 位十六进制字符串（`000001`、`00000a`…），不是序号。

### 批量提取各月汇总（趋势数据）

```bash
for sid in 000002 000003 000004 ...; do
  echo "=== $sid ==="
  python3 edsdk.py call sheet_get_cell_data file_id="<路径>" sheet_id=$sid \
    start_row=0 start_col=0 end_row=61 end_col=14 return_csv=true 2>&1 | python3 -c "
import sys,json,re
d=json.loads(re.search(r'\{.*\}',sys.stdin.read(),re.S).group(0))['csv_data']
lines=d.split('\n')
for i,l in enumerate(lines):
    if l.startswith('总计') or l.startswith('房产') or '我的负债' in l:
        print(l)
    if '月天数' in l and i+1 < len(lines):
        print('EFF>'+lines[i+1])
"
done
```

**不要** `close_file`，会关掉用户正在看的视图。

## 4. 强制交叉校验

读完最新月后立即验证：

```
Σ(各持仓最新价) == 总计行的最新价  ?
```

实测这一步能抓出：隐藏行、解析错位、分类 ffill 错误。**不等就不要往下做分析**，先定位差额来自哪一行。

同样校验负债：`Σ(各项现负债) == 负债总计行现负债`。

## 5. ⚠️ openpyxl 兜底通道的严重局限（实测踩坑，必读）

**结论先说：能用 editor_sdk 就绝不要用 openpyxl 读这类记账表。**

实测一份真实记账表（WPS/非 Excel 原生保存），openpyxl `data_only=True` 的结果与 editor_sdk 实时重算**大面积不一致**：

| 单元格 | openpyxl 缓存值 | editor_sdk 实时值 | 差异 |
|---|---|---|---|
| 总计·成本 | 856,332.035 | **863,167.97** | 陈旧（是上月的值） |
| 总计·最新价 | `None` | **902,939.33** | 无缓存 |
| 余额宝·成本 | 108,587.99 | **110,277.74** | 陈旧 |
| 国投证券·成本 | 42,053.32 | **16,207.86** | 陈旧（差 2.6 倍） |

### 根因有三层

**① 公式缓存陈旧或缺失**
该文件 33 个公式单元格中，多个 `<f>` 标签里写的是 `==G9-I9`（双等号，非标准）。这是非 Excel 写入器的产物——它写入公式但**不写/不更新计算缓存**。openpyxl 只会读缓存，不会计算，所以读到的是上一次某个版本的残留值。

**② 成本列本身是反推公式，不是录入值**
```
E成本 = =最新价 − 总收益     （E = G − I）
```
用户是用「现在值多少 − 赚了多少」反推成本。这意味着**成本列没有独立的原始数据**，缓存一旦陈旧就无法自行修复，手动重算也救不回来。

**③ 自己重算也会错**
试图用 openpyxl 读原始值自行 SUM：市值能对上（902,939.33 ✓，因为最新价是手工录入值），但成本差了 76,017.82——因为成本列本身就是公式。

### 操作结论

| 场景 | 通道 |
|---|---|
| 文件在用户本机 | **editor_sdk MCP（唯一可靠）** |
| 只能用 openpyxl | 仅可信任**手工录入的数值列**（最新价、原负债等）；所有公式列（成本、总收益、收益率、各级小计）必须视为不可信 |
| 两通道结果不一致 | **一律以 editor_sdk 为准**，并在报告里提示用户"表格缓存已陈旧，建议用 Excel 打开后重新保存一次" |

`scripts/dump_sheets.py` 已保留，但仅用于：① 快速 `--list` 看 sheet 清单 ② editor_sdk 完全不可用时的降级读取（此时必须向用户声明数据可能不准）。

## 6. 额外要检测的公式缺陷

除了"收益率符号错"，实测还存在两类更隐蔽的缺陷，务必逐一检查：

### 缺陷 A：公式引用了错误的列
```
不动产·总收益  I48 = =E48 − F48      ← 写成了「成本 − 上月价」
正确应为        I48 = =G48 − E48      ← 「最新价 − 成本」
```
双重错误（列错 + 符号反），且因 F48 留空按 0 计算，结果是 `总收益 = 成本`、`收益率 = +100%`。

### 缺陷 B：同一张表里求和范围不一致（最隐蔽）
```
E47 = SUM(E3:E46)   ← 成本，覆盖全部 44 个数据行 ✓
G47 = SUM(G3:G43)   ← 最新价，只到第 43 行，漏掉 3 行 ✗
```
当前漏掉的 3 行恰好是空仓，所以总数看起来是对的——**一旦这几行有持仓，总资产就会被少算且毫无提示**。

**检测方法**：用 `include_formula=true` 取各小计/总计单元格的公式，解析出 `SUM(X{a}:X{b})` 的 `a,b`，与实际数据行区间比对，任一不一致即报 P0。

```bash
python3 edsdk.py call sheet_get_cell_data file_id="<路径>" sheet_id=000001 \
  start_row=46 start_col=0 end_row=48 end_col=14 include_formula=true
```

## 7. 非 xlsx 输入

| 输入形式 | 处理 |
|---|---|
| 截图 | 直接读图识别数字，逐项向用户确认关键数（总资产/总负债/前三持仓）后再分析 |
| 文字清单 | 先结构化成表格回显给用户确认，再分析 |
| csv | `scripts/dump_sheets.py` 可直接用（csv 无公式，不存在缓存问题） |
| 多个文件 | 按时间排序合并成趋势序列 |

**绝对禁止**：数据不全时用演示数据/假设数据填充。缺什么就在报告里标注「数据缺失，影响 X 项判断」。
